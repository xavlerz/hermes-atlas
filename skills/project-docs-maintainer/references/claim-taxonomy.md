# Claim taxonomy

- **Factual:** directly confirmed in code, configuration, tests, command output, or an authoritative artifact; cite the source and date/commit where useful.
- **Inferred:** plausible explanation from evidence, not directly established; label it and explain what would confirm it.
- **Proposed:** intended future work or recommendation; do not imply approval, schedule, or implementation.

For architecture, describe files and actual flows, not aspirational design. For state, record baseline and exact checks. A passing static check does not establish runtime or production behavior.
